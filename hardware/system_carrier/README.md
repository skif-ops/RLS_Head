# EVT System Carrier

This directory contains the authoritative non-RF System Carrier electrical and production-input contracts.

The current Rev. A ECO has these interfaces:

- protected 12 V input and radar power output;
- CAN-FD and `RADAR_REF` for the external AWR2944PEVM radar;
- two independent 3.3 V host UART channels on J6;
- external simpleRTK3B Pro / mosaic-X5 GNSS on detachable JST-GH J8;
- GNSS UART, PPS and carrier-generated `5V_GNSS` on J8;
- IMU, SWD, reset, debug UART and status test points.

There is no Ethernet, onboard GNSS receiver, GNSS RF trace or 76-81 GHz RF implementation on this carrier.

## CAD authority

Altium Designer is the primary and release-authoritative CAD system. The current native project must contain the complete schematic hierarchy and PCB. Every released BOM, drawing, schematic PDF, multilayer PCB PDF, Gerber, drill, IPC-2581, pick-and-place, STEP and validation report must be generated by the current Altium project and its OutJob.

The retained KiCad project is used only as the import source and independent equivalence baseline. It is not a production-document source.

The previous native Altium import and equivalence evidence predate this UART and external-GNSS ECO. They are not current authority. Routing becomes authorized only after the new native import, compile, audit and `ALTIUM_EQUIVALENCE_GATE=PASS`.

Production authority remains `NOT_AUTHORIZED`.

## Compact board ECO

The former 100 x 80 mm outline is the maximum envelope. The current Altium placement contract evaluates a 90 x 70 mm candidate. The smaller outline can be locked only after component placement, routing, connector access, mounting-hole clearances and native DRC pass.

The enclosure is outside the pilot manufacturing scope and does not block the PCB archive. Only antenna mounts are prepared if later shown to be technologically necessary.

## Pilot fabrication baseline

The selected pilot manufacturer is Rezonit. The working stack is four layers, 1.60 mm board thickness and 35 um copper. The current architecture has no Ethernet MDI or onboard GNSS RF route, so the carrier needs no controlled-impedance structure.

Run the source checks before native import:

```text
python -m tools.carrier_design_inputs hardware/system_carrier --output carrier_design_inputs.json
python -m tools.carrier_schematic_contract hardware/system_carrier --output carrier_schematic_contract.json
```
