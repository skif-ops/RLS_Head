# Measurement readiness report\n\n`tools.measurement_readiness` converts the authoritative project evidence manifest into an execution-oriented view.\n\nIt does not create evidence and does not change project status.\n\nCurrent action classes:\n\n- `READY_FOR_EXTERNAL_EXECUTION` — software/contracts are ready; collect or create the external artifact.\n- `BLOCKED_TOOLING` — required validator/tooling is not PASS.\n- `BLOCKED_DEPENDENCY` — another authoritative evidence item must close first.\n- `CLOSED` — evidence item already PASS.\n- `FAILED_EVIDENCE` — the current evidence item is FAIL.\n\nRun:\n\n```bash\npython -m tools.measurement_readiness \\n  evidence/project_evidence_manifest.json \\n  --output measurement_readiness.json\n```\n\nThe report maps measured items to execution packs where one exists:\n\n- M300 -> `m300`\n- reference range -> `reference_range`\n- HIL-R2 bench -> `hil_r2_bench`\n- SYS-ERR -> `sys_err`\n- physical antenna -> `physical_antenna`\n- EVM profile -> `evm_profile`\n\nD1 EM and Carrier Review A have no measurement-pack kind because they are solver/CAD execution tasks rather than data-collection CSV packs.\n\nThe current baseline intentionally keeps SYS-ERR blocked on HIL-R2 bench evidence and physical antenna measurement blocked on M300 + real ANT-SIM + measured SYS-ERR.\n
